# ゲノモン

小さな生きもの「ゲノモン」を育て、かたちの違いを観察し、交配して次の世代を見るブラウザゲーム。

## 最短の起動手順

```bash
cd genomon
npm install
npm run dev
```

ブラウザで `http://localhost:5183` を開く。

## そのほかのコマンド

```bash
npm run build      # 型チェック＋本番ビルド（dist/ へ出力）
npm run preview    # 本番ビルドの確認
npm test           # ユニットテスト（Vitest）
npm run e2e        # E2E テスト（Playwright。PC幅とスマホ幅の両方を走らせる）
npm run typecheck  # 型チェックのみ
```

E2E を初めて動かすときはブラウザの取得が要る:

```bash
npx playwright install chromium
```

## 開発者向けツール

**Visual Lab / 開発者モード / Cards Lab**（開発サーバ専用。本番ビルドには含まれない）:

```
http://localhost:5183/lab.html            # Visual Lab
http://localhost:5183/lab.html?tab=dev    # 開発者モード
http://localhost:5183/lab.html?tab=cards  # Cards Lab
```

Visual Lab でできること: 任意 seed からの生成・同じ seed の再生成・ランダム seed・100体一覧・500体以上の自動検査・素体別／配色別の生成（潜性の `pearl`・`mineral` をホモ接合で強制できる）・卵/幼体/成体の切り替え・Genotype / Phenotype / RenderModel の表示・親を指定した兄弟生成・突然変異率の一時変更・明暗背景・大小サイズ・描画境界とアンカーの表示・描画順の1枚ずつ確認・問題 seed の保存・PNG 出力。

開発者モードでできること: 時間を進める／コイン追加／各ステータスの変更／即時孵化／即時成体化／各機能の解放／セーブ初期化／任意 seed の読み込み／個体データの JSON 確認／親を指定した交配／突然変異と特定形質の強制。

Cards Lab でできること: トレーディングカードの試作。既定は **Collector v2**（黒地・大きなゲノモン・段ごとに素材の変わる箔・鑑定機関の認証印・裏面の鑑定書）。比較用に Certified / Natural History / 旧 Collector も残してある。

- **段（希少度）** — STANDARD / NOTABLE / RARE / EXCEPTIONAL / MYTHIC の 5 段。ランク名・正確な点数・記号（◆◆◆◇◇）・**素材そのもの**（箔の量と掛かる場所・地紋・認証印・縁・帯）の 4 層で表す。実データから決まるが、美術研究のため段を強制表示できる（**見た目だけで、遺伝データは変わらない**）。
- **認証印** — 紙に押したインク → 縁だけ箔 → 銀箔 → 金箔 → ホロ箔。ギヨシェ・微細目盛り・二重らせんは証明書番号から決まる。カード幅の 34% あり、**個体ごとに位置・角度・大きさ・濃さ・押しムラが変わる**（seed 由来・同じ個体なら完全再現）。
- **裏返し** — カード本体をタップ（Enter / Space）で表 ↔ 裏。裏は表と同じ暗い素材の鑑定書で、遺伝の要約・主要な遺伝子座・血統・交配記録・展示記録・QR プレースホルダが載る。**遺伝情報だけは本編とまったく同じ計算**（親・展示成績は Lab 専用のダミー）。
- **裏面の図表** — 遺伝子構成の積み上げ帯／分布の中での位置（実測 20000 体の累積分布から算出）／数値形質 6 項目の横棒／血統の括弧図。すべて実データで、架空の固定値は無い。
- **比較** — 同一個体 × 5 段 / × 仕上げ 6 種 / × 版面 4 案 / 個体一覧 8〜30 枚。
- **次々にめくる** — PC はカードの真下の操作列（◀ ／ つぎのカード ／ 表・裏 ／ ♥）と、`←` `→` でめくる・`F` で裏返すキー操作。スマホは画面下のデッキバーと左右スワイプ。
- 箔の強さ・映り込み・傾き・箔の 3D・foil マスク・セキュリティ模様・明暗背景を調整でき、良い組み合わせは Cards Lab 専用キーへ保存できる。

分布の実測は `npx vite-node tools/cardStats.ts`（フレーバーの重複度と段の出現率）。

スマホでは、カードが最初に見える並びに切り替わり、画面下に**デッキバー**（戻る／つぎのカード／版面／箔／面／保存）が出る。左右スワイプでもめくれる。比較と一覧は畳んであり、開くまで作られない（1 タップで次のカードが出る速さを優先している）。裏面はスマホでは文字寸法を上げ、あふれるぶんを書類の中だけでスクロールさせる。

**カードシステムはまだゲーム本編に入っていない**（鑑定所・発行・所持・アルバム・マーケット・QR の実 URL・スナップショット保存は未実装）。Cards Lab は見た目を決めるための実験環境で、本編の挙動は一切変えていない。詳しくは [DESIGN_DECISIONS.md](DESIGN_DECISIONS.md) の D-034 と **D-042**。

Visual Lab は `genomon.dev.*` のキーしか書かず、本体セーブには触れない。Cards Lab も同じ接頭辞の専用キー（`genomon.dev.cardprefs.v1` / `genomon.dev.cardsaved.v1`）だけを使い、Visual Lab の設定も上書きしない。開発者モードは既定でメモリ上の状態だけを変更し、「セーブに書き込む」を明示的に押したときだけ保存する（その直前に現在のセーブを `genomon.dev.savebackup.v1` へ退避する）。

**コンタクトシート**（100体一覧）:

```
http://localhost:5183/sheet.html?n=100&stage=adult
```

URL パラメータ: `n`（体数）/ `stage=egg|juvenile|adult` / `base=maru|yurei|slime` / `bg=light|dark` / `size=small|large` / `seed=XXXX` / `detail=full|lite`

## 遊びかた

1. タイトルで「はじめる」
2. **9個の卵から3個を選ぶ**（確定前なら選び直せる）
3. 育成室で卵を世話する（温める・水分・声をかける・やさしく触れる・環境を整える）
4. **孵化**（通常プレイで1〜2分）
5. 幼体を育てる（えさ・みず・きれいにする・なでる・あそぶ・やすませる）
6. **成体になる** → 展示会が解放
7. 展示会に出す → コイン獲得 → **ショップが解放**
8. アイテムや装飾を買う（装飾は育成室の見た目に反映される）
9. 成体が2体そろうと **交配が解放**
10. 交配で卵が生まれる → 孵化させて親子を見比べる

**同じ世話ばかり繰り返すと効果が落ちる。** いろいろな世話をまわすほうが効率が良い設計になっている。

## 未実装（既知の制限）

**以下は指示書に含まれるが、今回のセッションでは完了していない。**

- **ビジュアル品質** — 厳格なビジュアル批評で**不合格（平均5.13/10）**。描画バグの一部（装飾のフラット塗り、slime のシルエット分散、幼体→成体の差分保証、口の小ささ、顔レイアウトの固定など）が未修正。詳細と残件は [VISUAL_QA.md](VISUAL_QA.md)
- **厳格なゲームプレイ批評** — 専任の批評エージェントを立てていない。リードの実機プレイで代替した。飼育員の長期的な給与バランスは今後のプレイログで再評価する
- **統合ループ** — 実ブラウザでの網羅的な統合テスト（所持枠上限付近・複数世代・ブラウザ再起動相当など）は未実施
- **UI の E2E** — 展示会・ショップ・交配の画面操作は E2E に含めていない（実時間が長いため、Vitest 側の `tests/progression.test.ts` が仮想時間で担当）
- **Visual Lab の本番同梱** — `lab.html` は `vite.config.ts` の入口に無いため開発サーバ専用。開発者機能が配布物へ漏れない担保でもあるが、本番で使いたい場合は入口の追加が要る
- **メモリリークの検査・描画速度の定量測定** — 未実施
- オンラインマーケット・他プレイヤーとの交換・ランキングは対象外（データ構造のみ `GameState.future` に予約）

## セーブデータ仕様

- 保存先: `localStorage`
  - `genomon.save.v1` … 本体
  - `genomon.save.backup` … 1世代前のバックアップ
- 形式: `{ version, savedAt, checksum, state }`（`SAVE_VERSION = 7`。v5→v6→v7 を連鎖移行）
- **外見は保存しない。** 保存されるのは `Genotype`（seed＋対立遺伝子ペア）と `LifeState` のみで、見た目は毎回そこから再構成する
- 本体が壊れていればバックアップから復旧し、両方壊れていれば読み取れた範囲を復元して続行するか新規開始するかを選べる
- 保存タイミング: 卵選択後・世話後・孵化後・成長後・展示会後・購入後・交配後・設定変更後・画面遷移時・20秒ごと

## 遺伝子仕様

各個体は `seed`（文字列）と、遺伝子座ごとの**対立遺伝子ペア**を持つ。

- **カテゴリ形質（26座）**: 素体・輪郭・目の数・目の形・瞳・目のきらめき・目のグラデ・まつげ・口・耳・耳先・触角・角・植物器官・羽・尾・結晶・首かざり・足・浮遊物・模様・2色・発光・質感・毛・配色（`CAT_LOCUS_IDS` の順）
  - **毛**（うぶ毛・もこもこ・つんつん・ぼさぼさ）は輪郭に沿って外向きに生える。頭頂ではなく全周へ散らすので、植物・角・触角と場所を奪い合わない（DESIGN_DECISIONS の D-037）。**もこもこだけは房そのものが輪郭になる**ので、体の輪郭を引かない（D-038）
  - `dominance`（優性度）が高いほうが発現。同値かつ両方 `coDominant` なら合成表現（例: このは＋はな → はなとこのは）
  - 「なし」を優性にしてあるため、装飾が全個体に生えることはない
  - 珍しい形質ほど潜性なので、保因されて数世代後に現れる
- **数値形質（24座）**: 大きさ・縦横比・ふくらみ・色相・補助色・彩度・明度・模様の密度／粗さ・透明感・発光・目の大きさ／間隔・羽の大きさ・左右差・成長の速さ・健康傾向・装飾量・性格6軸（`NUM_LOCUS_IDS` の順）
  - 表現は2つの対立遺伝子の平均＋ごく小さいゆらぎ
- **交配**: 各座について親A・親Bから独立に1つずつ受け継ぐ（メンデル分離）。突然変異は同一遺伝子座の**隣接する対立遺伝子**へ寄せるので、系統が保たれる

乱数は seed 付き PRNG（sfc32）のみを使い、**名前付きサブストリーム**（`rng.stream('ears')`）でパーツごとに独立させている。描画順やパーツの追加で既存個体の見た目が変わらない。

## ライセンス・素材

外部の著作権素材は使用していない。効果音はすべて Web Audio API による合成音。絵はすべて SVG パスで描画しており、絵文字やアイコン素材を生きもの本体に使っていない。
